- G1 camera-convention correlation selected `c2w_opencv` on all 8/8 sampled

  negative or near zero).
- `export_scannet_sequence.py` exported five trajectory-spanning 512x512 RGB,
  uint16-millimetre depth, intrinsics, and c2w pose frames as `scene9000_00`.
- Boxer's loader returned 10,000 finite semi-dense points for every frame.
- The first network attempt exposed a missing Triton build prerequisite;
  Ubuntu `python3.12-dev` and its 32.5 MB of dependencies were installed.
- The repeat completed on CUDA/bfloat16: 14 OWLv2 detections and 5 accepted
  Boxer 3D boxes across five frames in about 1.2 seconds after initialization.
- `adapt_boxer.py` converted the native quaternion OBB CSV to five benchmark
  AABB JSONL records in the original ScenePipeline world frame.
- Boxer's headless visualization additionally required Ubuntu `ffmpeg`; the
  completed repeat wrote five JPEG overlays and a 433 KB MP4. Frames 0, 2, and
  4 were inspected: RGB was upright, the sparse depth overlay was coherent,
  and predicted lighting-fixture, door, magazine, and coffee-table boxes
  projected onto their detected image regions.

The smoke output is machine-local under
`living_marble/lifting_benchmark_smoke/`. It is **not an accuracy result**:
only five views were used, fusion was disabled, and this scene has no exact
object GT. It establishes that RGB, metric depth, pose, labels, detector,
BoxerNet, CSV output, and the common-schema adapter all execute together.

- SAM2 under `Zoo3D/Zoo3D_0/third_party/sam2`, commit
  `2b90b9f5ceec907a1c18123530e92e794ad901a4`

No Zoo3D dataset or model weights were downloaded. The release is not a
self-contained install: a faithful setup still needs a compatible compiled
PyTorch3D stack, Detectron2 + CropFormer custom ops, Entity API, `mmdet3d`,
Open3D, OpenCLIP, SAM2-large weights, and a CropFormer checkpoint. Its current
runner also assumes ScanNet-style RGB/depth/poses, a reconstructed point cloud,
fixed frame IDs, and ScanNet evaluation metadata.

This makes Zoo3D the highest-risk adapter. Before installing the compiled
stack, create one benchmark scene in the expected data contract and decide
whether the primary comparison is its `posed_images` path or point-cloud path.
The paper plan currently calls for `Zoo3D_0` only; do not run self-training.

## Benchmark plumbing added

- `protocol.v0.json`: smoke schema, units, box convention, matching, and metrics.
- `adapt_splat_analyzer.py`: current `scale`/`frames` schema plus legacy `size`.
- `export_scannet_sequence.py`: verified RGB-D/pose export for Boxer's loader.
- `adapt_boxer.py`: native quaternion OBB to source-frame benchmark AABB.
- `evaluate.py`: AABB IoU, Hungarian paired errors, per-class AP25/AP50,
  recall, false discoveries, and duplicate counts.
- Tests cover both adapters, camera-axis conversion and frame selection,
  perfect predictions, known shifts, duplicates, empty predictions, and
  prediction-only categories.
